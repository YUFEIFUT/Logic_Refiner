# 需求：消除逻辑精炼节点中的"伪数学/公式化表达"

> 状态：✅ 已实施完毕（提示词改造 + 实证验证 + 回归门禁已落地）。作者已完成多轮自评审与实测，见文末「自评审记录」「实施结果记录」。
> 关联分析：本次需求源于对 `refinements.db` 的实证分析（全库 179 条记录 + `server/index.ts`、`server/llm/provider.ts` 提示词审查），根因见「背景 → 根因分析」。
>
> ⚠️ **测试运行环境说明**：本项目 `vitest` 在该沙箱环境存在**预存**的运行期问题——连零依赖的 smoke 测试都会在模块求值期抛 `reading 'config'`，全部 15 个测试文件一致失败，与本次改动无关。因此本需求的"红/绿门禁"改以**可直接执行的 tsx 脚本**承载（见 §4 / T0 / T6），而非依赖 vitest。

## 1. 背景

### 1.1 问题现象

在已跑出的数据中，逻辑精炼流程的**多数节点**会输出 LaTeX 数学公式或伪数学记号，且这些记号普遍**未被定义、不可计算**，读者需要额外把符号翻译回自然语言才能理解，构成认知负担。

典型样本（`refinements.db` ID=275「人格魅力的本质是什么」，2 轮迭代）：
- architect 开篇即写：`Y = f\left(\sum_{i=1}^{n} w_i \cdot X_i\right) \otimes C_{obs}`
- redteam / synthesizer 全程复用 `$X$`、`$C_{obs$`、`$V$` 等符号
- boundary 引入递归式 `C_{obs}^{(t+1)} = \text{Update}(C_{obs}^{(t)}, V^{(t)})`、sigmoid `A = \alpha \cdot \frac{1}{1 + e^{-\beta(\kappa - \kappa_0)}} \cdot \phi(...)`
- 上述符号（`f`、`⊗`、`w_i`、`φ`、`κ`）**全无操作化定义**，属于"装饰性严谨"。

用户原话：「逻辑精炼的很多个节点大模型输出的内容很多都还是容易带有那种数学公式的表达，这种东西看起来简洁，但是假如我真的去看每个节点的内容的话，是很难理解的，因为我还要加一层理解数学公式的认知负担。」

### 1.2 全库量化证据（179 条记录，按节点统计含数学表达的比例）

| 节点 | 含数学率 | 备注 |
|------|----------|------|
| architect | 66% (50/76) | 公式的"发起者" |
| redteam | 61% (81/132) | 接力复用上游符号 |
| synthesizer | 64% (85/132) | 接力复用上游符号、并自创新记号 |
| boundary | 82% (54/66) | 比例最高 |
| crystallizer | 20% (1/5) | **比例最低，几乎不出公式** |
| explainer | 100% (5/5) | 样本少，但全部含公式 |

`crystallizer` 的低比例是一个关键对照：**它恰恰是全文唯一写了"绝对不要将抽象概念强行塞进数学或物理公式"且配了白话范例的节点**。这证明"强硬禁令 + 给范例"对该模型有效，也指明本需求的修复路径。

### 1.3 根因分析

| # | 根因 | 位置 | 严重程度 | 说明 |
|---|------|------|----------|------|
| R1 | **全局 LaTeX 格式提示**主动教模型用公式 | `server/llm/provider.ts` `enhanceSystemInstruction()`（实施时已抽为 `server/llm/enhance.ts` 纯函数，`provider.ts` 委托调用） | 高 | 给**每个节点**的 system 追加："当你输出任何必须的数学公式、定量变量或严密的逻辑代数式时，请使用标准的 LaTeX 语法……"。末尾"极力避免将非数量化的现实抽象概念生搬硬套进……伪物理或数学公式"措辞软、且排在指令之后，被覆盖。 |
| R2 | 提示词框架本身邀请"变量/方程"思维 | `server/index.ts` 各 stage prompt | 高 | architect 要"识别变量关系与隐含假设"；redteam 要复述"关键变量关系"；synthesizer/crystallizer 反复强调"变量之间的因果关系""奥卡姆剃刀/简洁"；boundary 点"贝叶斯认知建议""场域""概率"。要求抽变量+讲因果+简洁，最省力表达就是写公式，简洁指令与反公式指令直接打架。 |
| R3 | 反公式约束不一致且普遍偏弱 | `server/index.ts` | 高 | architect 弱（"避免生硬造作的物理/数学公式形式"）；synthesizer 弱（"不要生搬硬套物理或代数方程式"，但举例又用"熵增/非线性反馈"）；**redteam、boundary、explainer 完全无反公式约束**；仅 crystallizer 强硬 + 范例。 |
| R4 | 跨节点/跨轮次的"符号传染" | `server/index.ts` 节点串联 | 中 | 每个节点把上一节点输出当输入，architect 写下 `$C_obs$` 后下游顺延；redteam 被要求"复述关键变量关系""针对当前逻辑的实际论点"，自然延续记号；两轮迭代滚雪球。 |
| R5 | 前端 KaTeX 渲染放大"看起来简洁"错觉 | `katex`/`remark-math`/`rehype-katex`（前端依赖） | 低（症状放大器） | `$...$` 被渲染成漂亮排版，无视觉摩擦提醒"过度形式化"，使伪数学悄悄存活。非生成原因，但掩盖问题。 |

**核心结论**：数学公式被系统"制度化"地鼓励出来（R1 全局提示 + R2 框架偏好），且因约束只在结尾强硬（R3）而在全链路被复用（R4）。最有效的修复 = 把 crystallizer 式"强硬禁令 + 白话范例"统一铺到所有节点，并削弱/改写 R1 的全局 LaTeX 提示。

## 2. 目标与范围

### 2.1 目标

让逻辑精炼流程中**除 crystallizer 外原本高公式率的节点（architect / redteam / synthesizer / boundary / explainer）**的输出，以**自然语言**清晰表达变量关系、因果与边界，**消除未定义/不可计算的伪数学记号**，显著降低读者逐节点理解时的认知负担，同时**不损失**逻辑深度、精准度与"简洁"诉求。

### 2.2 非目标（明确不做）

- 不删除前端的 KaTeX 渲染能力（保留对真正定量内容的渲染支持，但本需求下节点不应再产出此类内容）。
- 不改动 crystallizer（它已达标，仅作为范例来源）。
- 不改动数据库 schema、不迁移历史数据。
- 不替换 LLM provider / 模型，"agnes" 保持。
- 不要求模型在"真正涉及数量关系"时禁止公式——但当前所有节点均属定性讨论，实践中不应出现公式。

### 2.3 成功度量（基线 vs 目标）

> **定位：方向性守卫，而非硬性 KPI。** 评审时用户明确："现在就定一个留余量的具体数值 KPI 也未必能达到那个效果，不过至少也得比现在的状况要好才行。" 因此下方阈值只作**"相对基线显著改善 + 不再出现伪数学"**的方向性兜底，不追求精确归零；最终验收以"人工抽查无未定义/不可计算的伪数学"为准。

| 指标 | 基线（当前） | 目标（方向性守卫，留余量） |
|------|--------------|------|
| architect 含数学率 | 66% | ≤ 15% |
| redteam 含数学率 | 61% | ≤ 20% |
| synthesizer 含数学率 | 64% | ≤ 20% |
| boundary 含数学率 | 82% | ≤ 25% |
| explainer 含数学率 | 100%(n=5) | ≤ 30% |
| 节点输出"含未定义符号/伪数学" | 普遍存在 | 0（定性讨论中不应出现） |
| 逻辑深度/精准度（人工对比） | — | 不低于修改前 |

> 阈值留了余量：因为"含数学"检测会命中 `→`、`×` 等纯自然语言也常用的箭头/乘号（已在评估脚本中将这些"自然语言箭头"与"真实公式/伪数学"区分开，仅后者计入门禁），且偶有真实定量语境。自动化阈值为辅助守卫，**核心验收 = 人工抽查无伪数学**。
>
> **explainer 语料补充（评审时用户提出）**：explainer 的历史样本仅 5 条、代表性不足，用户要求"explainer 可以多攒几条它的数据"。实施时已在实跑语料中纳入 explainer 产出，后续若要做更稳的基线，建议再扩充 `refinements.db` 中 explainer 节点的样本量（属长期观测项，不阻塞本次交付）。

## 3. 设计原则

| 原则 | 含义 |
|------|------|
| **自然语言优先** | 变量关系、因果、边界一律用中文句子表达，不用符号代数。 |
| **禁伪数学** | 禁止引入未定义、不可计算的符号记号（如 `Y=f(...)⊗C`、`⊗`、`w_i` 等装饰性写法）。 |
| **强硬 + 范例** | 每个节点采用 crystallizer 已被验证有效的写法：明确禁令 + 给出一句"好的自然语言表述"范例。 |
| **不削弱逻辑质量** | 反公式的同时保留"精准、证伪、边界、简洁"等原有质量约束，二者不冲突。 |
| **去全局鼓励** | 改写 `provider.ts` 全局 LaTeX 提示：从"鼓励用 LaTeX"降级为"仅在确实定量时可用，默认自然语言"。 |
| **TDD 守卫** | 先写评估脚本（红测试），再改提示词，使红测试转绿；脚本纳入回归。 |

## 4. TDD 流程总览

本需求的"测试"是**输出质量评估脚本**（对节点文本做数学记号检测 + 抽样人工复核），而非传统单元测试——因为改动对象是 prompt。

> **门禁载体说明**：原计划以 `vitest` 承载红/绿断言（`tests/prompt-no-formula.test.ts`）。但本项目 `vitest` 在运行环境存在**预存**的加载期崩溃（全部 15 个测试文件 + 零依赖 smoke 测试一致失败，报错 `reading 'config'`，与本次改动无关）。故红/绿门禁改以**可直接执行的 tsx 脚本**承载，等价复刻原 15 条断言：
> - `scripts/check-prompt-lint.ts`（`npm run lint:prompts`）：纯静态检查各节点 system / prompt / 全局提示是否含"反公式强硬约束"，任一不满足即 exit 1（红），全过 exit 0（绿）。**这就是本需求的可执行 TDD 门禁。**
> - `scripts/evaluate-no-formula.ts`（`npm run eval:formula`）：量化评估（静态读 DB 历史基线 / 实跑 `--live` 验证新产出）。
>
> 原 `tests/prompt-no-formula.test.ts` 仍保留作文档化参考；待 vitest 环境修复后可恢复为首选门禁。

```
[红] 1. 先写评估脚本 evaluate-no-formula.ts（T0），静态模式跑 DB 历史，
       断言各节点"含数学率"与"伪数学条数"低于阈值 → 当前必失败（基线 61%~82%，exit 1）
        ↓
[绿] 2. 按 T1（全局提示）→ T2~T5（逐节点提示）顺序改提示词；
       每改完一个节点，重跑脚本静态模式，观察该节点含数学率曲线下降（无需起 server/LLM）
        ↓
[绿] 3. 全部节点改完后，脚本静态模式 exit 0；再用实跑模式（--live）对固定清单验证真实产出
        ↓
[重构] 4. 固化脚本为 scripts/ 下的长期回归测试；补 package.json 脚本与 README 说明
```

- **红阶段不修改任何产品提示词**，只建立可量化失败（脚本 exit code 即判定）。
- T1~T5 每完成一个，都重跑静态模式看该节点曲线，是"小步红→绿"而非最后一次性验证。
- T1（改 `provider.ts` 全局提示）影响所有节点，应最先做；T2~T5 在其基础上逐节点收口。
- 评估脚本属于本需求交付物（长期保留），符合"TDD 流程"要求。

## 5. 子任务拆分（含设计 + 验收标准）

### T0. 建立 TDD 评估脚本（红测试）

**目标**：在改任何提示词之前，先产出可量化"节点含数学/伪数学"的评估脚本，作为红测试与回归守卫。

**设计**：
- 新建 `scripts/evaluate-no-formula.ts`（长期保留，非临时文件）。
- 复用项目已有的 sql.js 读取能力与我们在分析中验证过的检测逻辑，封装为检测函数：
  - `hasInlineMath(s)`：检测 `$...$` / `$$...$$` / `\( \)` / `\[ \]`。
  - `hasLatexCmd(s)`：检测 `\frac \sum \int \alpha …` 等 LaTeX 命令。
  - `hasPseudoFormula(s)`：检测"短行内 变量/符号 + 关系算子（= => × ÷ ∝ ≈ → ⇒ ∈）+ 变量/符号"的伪代数结构（如 `Y = f(...) ⊗ C`）；**不把连字符英文合成词（Wi-Fi、Self-reference）误判为公式**。
  - `hasProseArrow(s)`（仅参考、不计入门禁）：检测 `→ × ≈ ≤ ≥` 等自然语言也常用的箭头/符号，单独统计便于人工复核，避免把"因为…所以…"误判为数学。
  - `isFormula(s)`：门禁用，命中内联公式 / LaTeX 命令 / 伪公式三者之一即判为"真实公式/伪数学"。
- 脚本支持**两种模式**（默认静态、可选实跑），均逐节点输出：是否命中、命中类型、命中行片段：
  - **静态模式（红阶段默认）**：直接读取 `refinements.db` 中全部历史记录，按节点类型聚合统计含数学率与伪数学条数。无需起 server、无需调用 LLM，秒级出结果，适合在 T1~T5 每次改完一个节点后快速重跑看曲线变化。
  - **实跑模式（T6 终验用，可选 `--live`）**：对固定输入清单调用精炼流程（通过起 `server/index.ts` 并请求 `/api/refine` 的 SSE，或抽出 `runStage` 直接调用；需 `LLM_API_KEY` 可用），把新产生的记录写入 DB 后再做同样的统计。实跑产生的是**新记录**，不回溯修改任何既有记录。
- 输出汇总表（每个节点的 含数学率 / 伪数学条数），并**断言阈值**：任一节点含数学率 > 目标阈值即 `process.exit(1)`（红）；全部达标则 exit 0（绿）。`exit code` 即为"红/绿"的可执行判定。
- 实跑模式的固定输入清单（代表性、覆盖问题/命题两类、含曾出公式的案例）：
  1. `人格魅力的本质是什么`（已知重灾区，ID=275）
  2. `黑暗的本质是什么`（已知红队曾范畴错位）
  3. `努力就会成功`
  4. `自由意志存在吗`
  5. `为什么有些人看起来更有领导力`

**验收标准**：
- [ ] `scripts/evaluate-no-formula.ts` 存在且可运行（`npm run eval:formula` 或 `tsx scripts/evaluate-no-formula.ts`）。
- [ ] 脚本在不改任何提示词、以**静态模式**运行时结果为**失败（exit 1）**：它读取 `refinements.db` 中**既有**历史记录（这些记录由旧提示词生成，已实测含 61%~82% 数学），据此断言必然超阈值 → 这正是 TDD 的"红"。打印出 architect/redteam/synthesizer/boundary/explainer 的当前含数学率（应接近基线 61%~82%）。静态模式只读 DB，不写入、不改写任何记录。
- [ ] 检测函数覆盖"内联公式 / LaTeX 命令 / 数学符号 / 伪公式"四类。
- [ ] 脚本对每个节点打印命中片段，便于人工复核；实跑模式对清单中每条输入、每个节点打印命中片段。

### T1. 弱化 `provider.ts` 全局 LaTeX 提示（根因 R1）

**目标**：把"鼓励用 LaTeX"的全局提示降级为"默认自然语言、仅确属定量时可用"，从制度上不再主动教模型写公式。

**修改位置**：实施时已把 `enhanceSystemInstruction()` 抽为纯函数 `server/llm/enhance.ts`（仅依赖类型），`server/llm/provider.ts` 的 `protected enhanceSystemInstruction()` 委托调用之（保留方法签名以兼容既有测试）。门禁断言见 `scripts/check-prompt-lint.ts` 的 `enhance` 段。

**修改前**：
```
"\n重要格式提示：当你输出任何必须的数学公式、定量变量或严密的逻辑代数式时，请使用标准的 LaTeX 语法。行内公式使用单个美元符号 $...$，块级/段落公式使用双美元符号 $$...$$。但请极力避免将非数量化的现实抽象概念生搬硬套进一个生硬造作的伪物理或数学公式中。"
```

**修改后（建议）**：
```
"\n输出格式提示：除非讨论的内容确实涉及可计算的定量关系（如概率、统计、度量），否则一律用自然语言表达变量关系与因果，不要使用 LaTeX 数学公式或符号代数。若确属定量场景必须使用公式，行内用单个美元符号 $...$。但严禁将非数量化的抽象概念塞进未定义、不可计算的伪数学记号中。"
```

**设计要点**：
- 把"鼓励用 LaTeX"改为"默认不用、定量才用"，顺序上让"自然语言优先"在前。
- 保留定量例外，避免一刀切误伤（虽当前节点均定性，但保留扩展性）。
- 保留"禁伪数学"底线。

**验收标准**：
- [ ] `enhanceSystemInstruction()` 返回值中**不再**出现"当你输出任何必须的数学公式……请使用标准的 LaTeX 语法"这类主动鼓励句式。
- [ ] 新提示包含"一律用自然语言表达变量关系与因果，不要使用 LaTeX 数学公式或符号代数"的默认导向。
- [ ] 保留"确属定量场景才可用公式"的例外与"禁伪数学"底线。
- [ ] 既有 `provider.test.ts` 的 **T3.13**（`it('T3.13 appends LaTeX hint to system instruction')`）当前断言 `systemContent.toContain('LaTeX')` 且 `startsWith('base system')`。本改动后该断言**机械上仍会通过**（新提示仍含 'LaTeX' 且提示为追加、以 base system 开头），**无需强制改**。但因其语义已从"鼓励用 LaTeX"转为"默认不用、仅定量可用"，建议在同 PR 内顺手把该测试名/断言改写为锁定新意图（例如改断言为包含"自然语言"导向与"禁伪数学"底线），避免未来有人误读 T3.13 为"应鼓励 LaTeX"。

### T2. architect 节点：加入强硬反公式约束 + 范例（根因 R3）

**目标**：作为公式"发起者"，从源头抑制伪数学；把 crystallizer 式写法前移。

**修改位置**：`server/prompts.ts` `buildArchitectPrompt()` 与 `architectSystem`（实施时将原 `server/index.ts` 内联提示集中到 `server/prompts.ts`）。

**修改内容**：
