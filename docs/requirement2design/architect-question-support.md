# 需求：Architect prompt 兼容问题类输入

## 背景

### 问题描述

当前 Architect 的 prompt 设计假设用户输入是一个"观点"或"命题"（如"努力就会成功"），但用户也可能输入一个问题（如"黑暗的本质是什么"、"为什么有些人不努力也能成功"）。

当前 prompt：
```
将以下观点转化为基本的核心因果逻辑结构，识别观点背后的变量关系与隐含假设。
```

这个 prompt 对问题类输入存在以下不足：
1. **缺乏立场**：问题本身没有"观点"可供解构，Architect 可能输出一个泛泛的问题分析而非一个可被证伪的逻辑结构
2. **下游断裂**：Red Team 需要一个具体的逻辑结构来攻击，如果 Architect 输出的是问题分析而非立场，Red Team 无从下手
3. **"观点"用词局限**：prompt 中的"观点"一词对问题类输入不够自然

### 目标

在不改变整体流程结构的前提下，让 Architect 的 prompt 同时兼容问题和命题两类输入：
- **命题类输入**（如"努力就会成功"）：保持现有行为，直接解构逻辑结构
- **问题类输入**（如"黑暗的本质是什么"）：先给出一个初步回答/立场，再对该立场进行逻辑解构

### 设计原则

| 原则 | 含义 |
|------|------|
| **不改流程** | 不增加前置检测步骤，不增加额外 API 调用 |
| **最小改动** | 仅调整 Architect 的 prompt 和 system prompt |
| **输出格式一致** | 无论输入类型，Architect 的输出都是一个可被 Red Team 攻击的逻辑结构 |

## 子任务

### 4.1 修改 Architect prompt

**目标**：让 Architect 在面对问题类输入时，先给出一个明确的初始回答/立场，再进行逻辑解构。

**修改位置**：`server.ts` 第 185-188 行（`architectPrompt` 和 `architectSystem`）

**设计思路**：

当前 prompt 的核心指令是"将以下观点转化为核心因果逻辑结构"。对问题类输入，需要增加一个"先回答，再解构"的步骤。但这个步骤不应该让 Architect 的输出变长或改变格式——它应该仍然是一个逻辑结构，只是这个结构是基于对问题的回答建立的。

**修改方案**：

`architectPrompt` 改为：
```
将以下输入转化为基本的核心因果逻辑结构，识别背后的变量关系与隐含假设。

如果输入是一个问题，先给出一个你认为最合理、最有解释力的初步回答或立场，然后对该回答进行逻辑解构。
如果输入是一个观点或命题，直接进行逻辑解构。

【注意】：请避免使用生硬、造作的物理/数学公式形式。关注于核心概念之间的因果推导与哲学结构。
【输出要求】：最终输出必须是一个明确的、可被证伪的逻辑结构（而非一个问题分析或开放式讨论），便于后续进行压力测试。

输入： "${input}"
```

`architectSystem` 改为：
```
你是 'The Architect'（架构师）。你的任务是剖析表面观点的因果链条，发现隐藏的底层变量，输出清晰的逻辑演绎和核心假设。无论输入是问题还是命题，你都必须产出一个明确的逻辑立场作为后续精炼的起点。请使用中文。
```

**验收标准**：
- [x] `architectPrompt` 包含对问题类输入的处理指引（先回答，再解构）
- [x] `architectPrompt` 包含"输出必须是可被证伪的逻辑结构"的约束
- [x] `architectSystem` 包含"无论输入是问题还是命题，都必须产出明确逻辑立场"的约束
- [ ] 手动验证：输入"黑暗的本质是什么"，Architect 输出一个明确的逻辑立场（而非开放式问题分析）
- [ ] 手动验证：输入"努力就会成功"，Architect 输出与修改前行为一致

### 4.3 验证：问题类输入端到端测试

**目标**：确保问题类输入能走完整个精炼流程，且产出质量合理。

**测试用例**：

| 输入 | 预期 Architect 行为 | 预期流程表现 |
|------|---------------------|-------------|
| "黑暗的本质是什么" | 给出一个关于黑暗本质的明确立场（如"黑暗是光的缺失在认知层面的映射"），然后解构其逻辑 | Red Team 能针对该立场找到有效反例，流程正常完成 |
| "为什么有些人不努力也能成功" | 给出一个因果解释立场，然后解构 | 同上 |
| "努力就会成功"（回归测试） | 直接解构逻辑结构，与修改前行为一致 | 同上 |

**验收标准**：
- [ ] 对"黑暗的本质是什么"跑 2 轮迭代，Architect 输出包含明确立场
- [ ] 对"黑暗的本质是什么"跑完整流程，无报错，产出合理
- [ ] 对"努力就会成功"跑完整流程，产出与修改前一致
