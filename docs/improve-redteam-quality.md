# 需求：提升红队反驳质量——从"杠精式无差别攻击"到"精准深度批评"

## 背景

### 问题描述

当前红队（Red Team）的 prompt 设计导致其产出的反驳质量不稳定，存在以下典型问题：

1. **稻草人谬误**：红队曲解原逻辑后再攻击曲解后的版本。例如讨论"阴影的本质"时，原逻辑说的是"光的强弱对比所产生的视觉效果"，红队将其简化为"阴影=没有光"后再反驳"阴影并非仅仅是没有光"——而实际上原逻辑从未做过这个断言。

2. **范畴错位**：在哲学/认知层面的讨论中硬拉物理极端场景。例如讨论"黑暗的本质"时，红队提出"量子真空涨落"作为反例——原问题在讨论认知现象，红队却用量子物理来反驳，属于偷换讨论层级。

3. **未读对方回应就重复反驳**：合成器第一轮已经明确处理了某个问题（如引入"动态阈值"解释相对性），红队第二轮仍然拿同一个点来反驳，说明它没有认真理解合成器的回应。

### 实际案例佐证

以数据库中"黑暗的本质"（ID=43）为例：

**红队第一轮反例分析**：
- "深海无视觉生物"——**有效**，打中了人类视觉中心主义盲区
- "感官剥夺实验"——**有效**，挑战了"黑暗=消极缺失"的二元框架
- "量子真空涨落"——**无效**，范畴错位，原问题是哲学/认知层面的
- "先天盲人"——**有效**，概念建构差异论证

**红队第二轮反例分析**：
- "光子计数器"——**部分有效**，但合成器已区分了"基底层"和"现象层"
- "阈值悖论"——**无效**，合成器第一轮已明确引入"动态阈值"概念，红队未理解就反驳
- "黑暗餐厅/暗房"——**有效**，挑战了因果方向
- "宇宙学视界"——**无效**，与量子真空同类问题，极端物理场景滥用

**无效反例占比：4/8 = 50%**。这些无效反例不仅浪费迭代轮次，还可能将合成器的逻辑演化方向带偏。

### 根因分析

| # | 问题 | 位置 | 严重程度 |
|---|------|------|----------|
| 1 | System prompt 定位"极致的怀疑论者"，天然鼓励无差别攻击 | `server.ts:142` | 高 |
| 2 | 缺少"先理解再反驳"的步骤，红队可以跳过理解直接攻击 | `server.ts:135-141` | 高 |
| 3 | 合成器被迫消化所有反例，无质量过滤机制 | `server.ts:149-160` | 高 |
| 4 | 未约束反例必须在当前讨论层级内有效 | `server.ts:135-141` | 中 |

---

## 设计原则

| 原则 | 含义 |
|------|------|
| **先理解再反驳** | 红队必须先确认自己理解了当前逻辑的核心论点，再提出反例 |
| **精准打击** | 反例必须针对当前逻辑的实际弱点，而非稻草人 |
| **层级一致** | 反例必须在当前逻辑的讨论层级内有效，不得偷换范畴 |
| **质量过滤** | 合成器有权判定反例是否成立，不成立的反例不予吸收 |

---

## 子任务

### 2.1 红队 prompt 加入"理解确认"步骤

**目标**：在红队提出反例之前，强制它先用自己的话复述当前逻辑的核心论点，确保它真正理解了再攻击。这能过滤掉"未读对方回应就重复反驳"和"稻草人谬误"两类问题。

**修改位置**：`server.ts` 第 135-141 行（`redTeamPrompt`）

**修改内容**：将 prompt 从直接要求反例，改为分两步：

```
基于此逻辑结构：
原始观点： "${input}"
当前逻辑： ${currentLogic}
${lastRefinement ? `上一轮修正要点： ${lastRefinement}` : ""}

请按以下步骤进行：

第一步：理解确认
用你自己的话，简要复述当前逻辑的核心论点和关键变量关系（2-3 句话）。
这一步的目的是确认你真正理解了对方在说什么，而不是攻击一个你误解的版本。

第二步：精准反驳
基于你的理解，列出 3-5 个有力的反例或边界情况。每个反例必须：
1. 针对当前逻辑的实际论点，而非你复述时可能引入的简化
2. 在当前逻辑的讨论层级内有效（如逻辑在讨论认知现象，就不得用量子物理等不同层级的场景来反驳）
3. 说明该反例具体击中了当前逻辑的哪个环节（前提、推理链条、隐含假设）
```

**验收标准**：
- [x] 红队 prompt 包含"第一步：理解确认"步骤
- [x] 红队 prompt 要求复述当前逻辑的核心论点（2-3 句话）
- [x] 红队 prompt 包含"在当前逻辑的讨论层级内有效"的约束
- [x] 红队 prompt 要求每个反例说明击中了哪个环节
- [ ] 手动验证：输入"黑暗的本质是什么"，红队第一轮不再出现"量子真空涨落"类范畴错位反例

### 2.2 红队 system prompt 重新定位角色

**目标**：将红队从"极致的怀疑论者"改为"精准的批评者"，强调深度理解后的精准打击而非无差别攻击。

**修改位置**：`server.ts` 第 142 行（`redTeamSystem`）

**修改内容**：

```
// 旧
"你是 'The Red Team'。你是一个极致的怀疑论者。你的任务是找出当前逻辑在现实世界中无法闭环的证据。请使用中文。"

// 新
"你是 'The Red Team'。你是一个精准的逻辑批评者。你的任务是深入理解当前逻辑后，找出其在现实世界中无法闭环的关键弱点。你的反驳必须建立在对原逻辑的准确理解之上，攻击实际的逻辑缺陷，而非曲解后的稻草人。请使用中文。"
```

**验收标准**：
- [x] `redTeamSystem` 不再包含"极致的怀疑论者"
- [x] `redTeamSystem` 包含"精准的逻辑批评者"或类似定位
- [x] `redTeamSystem` 包含"准确理解"和"攻击实际逻辑缺陷"的约束

### 2.3 合成器加入反例质量评估步骤

**目标**：让合成器在吸收反例之前，先判断每个反例是否成立、是否切中要害。对不成立或重复的反例明确标注理由，而非默认全部吸收。这能防止无效反例污染逻辑演化方向。

**修改位置**：`server.ts` 第 149-160 行（`synthesizerPrompt`）

**修改内容**：在现有 prompt 的最前面加入质量评估步骤。同时需要将 `lastRefinement`（上一轮修正要点）传入合成器 prompt，以便合成器判断反例是否已被上一轮处理。注意 `lastRefinement` 每轮直接覆盖而非累加，不会导致 prompt 膨胀。

```
原始观点： "${input}"
当前逻辑： ${currentLogic}
红方反例： ${redTeamOutput}
${lastRefinement ? `上一轮修正要点： ${lastRefinement}` : ""}

请按以下步骤进行：

第一步：反例质量评估
逐个审视红方的反例，判断其有效性：
- 对于成立的反例：说明它击中了当前逻辑的哪个具体弱点
- 对于不成立的反例：说明为什么不成立（如：曲解了原逻辑、范畴错位、与当前逻辑已处理的问题重复）
- 对于重复的反例（当前逻辑已覆盖或上一轮修正要点已处理）：标注为已覆盖

第二步：逻辑精炼
仅基于你判定为有效的反例，对逻辑进行"非线性"提炼。
（后续保留原有 1-6 条约束不变）
```

**验收标准**：
- [x] `synthesizerPrompt` 包含"第一步：反例质量评估"
- [x] 评估步骤要求区分"成立/不成立/重复"三类反例
- [x] 评估步骤要求对不成立的反例说明理由
- [x] 逻辑精炼步骤明确"仅基于有效反例"
- [ ] 手动验证：输入"黑暗的本质是什么"，合成器不再被"阈值悖论"等已处理的反例带偏

---

### 2.4 验证：端到端回归测试

**目标**：确保修改后整个流程产出质量提升，且不引入新问题。

**验证方法**：使用相同的输入运行完整流程，对比修改前后的红队反例质量。

**测试用例**：

| 输入 | 预期改进 |
|------|----------|
| "黑暗的本质是什么" | 红队不再出现"量子真空涨落""宇宙学视界"等范畴错位反例；第二轮不再重复已被合成器处理的论点 |
| "阴影仅仅是没有光吗" | 红队不再曲解为"阴影=没有光"后再反驳；反例应针对"光的强弱对比"这一实际论点 |
| "努力就会成功" | 红队反例应针对具体的因果关系，而非泛泛地举"有些人不努力也成功了" |

**验收标准**：
- [ ] 对"黑暗的本质是什么"跑 2 轮迭代，红队无效反例占比从 ~50% 降至 <20%
- [ ] 合成器输出中不再出现对无效反例的回应或吸收
- [ ] 最终精炼逻辑的深度和准确性不低于修改前（人工对比）
- [ ] 流程正常完成，无报错
